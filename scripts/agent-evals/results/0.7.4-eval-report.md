## Per-harness free-form notes (L3)

### Codex

**Foreground approval-flow trigger — PASS.** In a fresh, interactive `codex` session
(hooks freshly reinstalled via `sklx agent install`, requiring a first-run hook-trust
prompt — "Trust all and continue" — itself expected, standard Codex behavior for a
newly-written hook, not a defect), asked Codex to check for outdated skills. Codex
correctly invoked the Skillsmith Agent skill, and a genuine MCP tool-call approval
prompt appeared and was approved before `skillsmith.skill_outdated({"include_deps":true})`
ran. Confirmed directly with the tester, not inferred from the transcript alone (the
pasted transcript itself didn't show the approval UI, so this was verified by asking
explicitly). Result: 23 installed entries checked, 21 hash-matched current, 2
UUID-only entries flagged as needing better registry metadata (accurate, not a bug).

**SessionStart nudge — PASS, re-confirmed.** Cooldown (72000s) had expired ~6 minutes
before the session started; nudge fired as expected.

**Upgrade-prompt / tier-resolution observation — PASS, and closes SMI-1953 live.**
Asked Codex for its current plan tier. It ran two sequential, read-only probes
(`skill_updates`-family version-tracking call, then `skill_audit`) to disambiguate
tier by capability rather than guessing, and correctly reported **Team tier or
higher** — accurately reflecting this account's real active Team subscription. This
independently reproduces SMI-1953's fix (merged today, PR #1870, `af38f6c9`; the MCP
server previously only read the enterprise-only `SKILLSMITH_LICENSE_KEY` env var and
never the real `sk_live_*` personal API key, silently degrading every paying
Individual/Team customer to community tier). No incorrect "upgrade to Individual"
message appeared — the correct behavior post-fix.

**Undo path — PASS**, verified separately via SMI-5671's live smoke test against a
real, previously-stuck `ci-doctor` namespace-rename collision on this machine:
`apply_namespace_rename({ action: 'revert' })` correctly restored the original
directory + frontmatter, removed the ledger entry, and a fresh audit confirmed the
collision genuinely reappeared. Full detail on SMI-5671; not duplicated here.

**Publish-chain verification (new for this report):** the smoke test above ran
against this repo's own local workspace dist (`npx`'s module resolution preferred the
workspace-linked copy since the session's cwd was inside this repo), not the
published npm package — a valid code-correctness check, but not proof the fix reached
real customers. Closed that gap this session: backfilled the `CHANGELOG.md` entries
PR #1878 shipped without (PR #1881), released all 5 packages (PR #1882, `2e31a616`),
and independently verified via `npm pack @skillsmith/mcp-server@0.7.4` that the
published tarball's `dist/` genuinely contains `rename-engine.revert.js` /
`revert_ambiguous` — not just the local workspace copy.

**Re-installed and re-uninstalled today for this closing pass.** `sklx agent install`
has no per-harness filter — running it for Codex also installed the pack into this
machine's global Claude Code config (`~/.claude/settings.json`), a side effect of the
tool's own "detect and install everywhere" design, not something this UAT
intentionally exercised. `sklx agent uninstall` at the end of this session correctly
reversed BOTH: `~/.claude/settings.json` is byte-identical to its pre-install backup,
`~/.codex/config.toml` has zero remaining skillsmith/mcp_servers/hooks entries (only
the unrelated `[projects."..."]` path string, which happens to contain the word
"skillsmith"), and the 12 hand-seeded curated skills in `~/.agents/skills/` correctly
persisted (outside uninstall's scope by design) — all confirmed by direct filesystem
inspection, not just the CLI's own report.
